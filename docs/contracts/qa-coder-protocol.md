# Contract: QA / Coder protocol (lane A)

The sequence of architecture section 4. Every step is orchestrator code; agents only edit files inside their sandbox.

**Who runs it (integrated, Phase 4).** `guard_agents::pipeline::TicketPipeline` drives the sequence (attempt loop, seal, Coder attempts, best-of-N, PR) through the ports and its seams (`guard_agents::pipeline::seams`). The seams are implemented by `guard-cli` (`agent_lane::checks::HostChecks`: quality, red-first, diff scanner, gate; `agent_lane::host::{HostLayout, LocalBranchPublisher, CodeHostPublisher}`). Red-first and the gate run in check sandboxes (`guard_sandbox::check`, below); quality and the diff scanner run on the host. They reuse `guard-sandbox`'s quality checker (`NodeSpecQuality`) and Playwright report parser (`SpecRun`). `guard_sandbox::harness::Harness` is an equivalent standalone harness kept with its tests; production uses the `guard-agents` pipeline. Each step records an `agent_runs` row (`outcome` column) and the decision log keeps the ticket-level result.

## Sequence

1. **QA attempt** (fresh sandbox, `role = qa`, sandbox.md). `task.json` with `allowed_paths = AllowedPaths::qa(tests_dir, KEY)`: write exactly `<tests>/features/<KEY>.spec.ts`. QA uses Playwright MCP against the preview environment.
2. **QA diff check.** `extract_diff`; any path in `allowed_paths.violations(changed_paths)` → `outcome = diff_rejected`, nothing is sealed.
3. **Test quality (deterministic, TypeScript compiler API on the spec, `guard-sandbox/assets/spec-quality.mjs`; list below).** Any failure → `quality_rejected`, back to QA (within QA's `max_attempts`) or the human lane. Only then the Jev Noul `test_has_meaningful_assertions` runs, with comments stripped from its `state`; below the threshold → human review.
4. **Red-first.** On a clean checkout of `base_commit` (never the QA worktree) the orchestrator runs only that spec. It **must fail** with at least one assertion failure (not a syntax/compile error, not a timeout of the app start). If it passes → `red_first_passed`: the test proves nothing new; back to QA or the human. If it fails without an assertion failure (load/compile error, thrown error, timeout) → `quality_rejected` with a `red-first: ...` detail. The run happens in a **check sandbox** (`DockerSandbox::create_check`): a fresh container from the agent sandbox image with the agent sandbox's hardening (`--read-only`, `--cap-drop ALL`, no-new-privileges, uid 1000, pids/cpu/memory limits, `runsc` when available), on its own `--internal` network with no egress forwarder and `--dns 127.0.0.1`, no host path mounted, `/workspace` a 1024 MB tmpfs. The candidate tree (`base_commit` plus the spec) is built on the host with git and a temporary index (the checkout, its index and worktree are never touched; in-tree `.gitattributes` cannot change files) and streamed in as a tar. Inside, the driver links the image's global `@playwright/test` (the candidate's own copy is removed, so the image's version must match `e2e-playwright`'s), starts `[app].start` with `PORT=3000`, waits for `[app].ready_path`, and runs Playwright with the JSON reporter on that spec only. The report, app log, Playwright stderr and up to 50 screenshots are copied out to `<work_root>/check-results/<check>/`; the sandbox is always destroyed. A sandbox or daemon failure is an infrastructure error, not an outcome. `GUARD_UNSAFE_HOST_CHECKS=1` (exactly `1`; development only, with an UNSAFE warning at lane build and before every check) runs the check on the host instead, from a clean worktree with `PORT=<free port>`.
5. **Seal.** `SealedSpec::seal(path, bytes)` → `{path, sha256}` (SHA-256 of the exact bytes, lowercase hex). The bytes go to orchestrator storage (`EvidenceStore` key `sealed/<run_id>/<KEY>.spec.ts`), the digest to `agent_runs.sealed_spec_sha256`. From here on, the spec is read only from that copy and verified with `SealedSpec::verify` before every use.
6. **Coder attempt `n`** (fresh sandbox per attempt, `role = coder`). `allowed_paths = AllowedPaths::coder(app_paths, tests_dir, &sealed)`: write the app paths (`[agents]` or `target.toml` areas of the ticket), deny `<tests>/**`, the sealed spec path and `CODER_PROTECTED_FILES` (manifests, lockfiles, `target.toml`, `thresholds.toml`, `agents.toml`, `playwright.config.*`, CI files; at any depth, so `apps/shop/package.json` is denied too). The sealed spec is bind-mounted read-only; journeys and smoke are hidden. On retries, `failure_context` carries the summary and trace of the failing tests only.
7. **Coder diff check.** The paths judged are those of the patch headers (`diff --git a/<p> b/<p>`, `---`/`+++`), which decide what `git apply` changes on the host; a header without the `a/`/`b/` prefixes, a quoted header, or a header path missing from `changed_paths` → `diff_rejected`; every path of either list is checked. Violations → `diff_rejected` (counts as an attempt). The diff scanner of section 4 (`guard_agents::scanner`: `test_env_detection` on added lines, `test_hook_in_logic` for added conditions on `testid` / `seed`, `removed_guard` for removed rejecting lines in auth / session / permission / payment / billing / checkout paths) → human lane.
8. **Finalize / gate.** On a clean checkout of `base_commit`: apply the Coder diff (`git apply --index`), then **overlay the sealed spec from orchestrator storage** (overwriting whatever is at its path), verify its hash, and run the section-3 selection (affected journeys + the sealed spec + smoke). Never run tests from the Coder's workspace. Green → `passed`: push branch `agent/<KEY>`, open the PR (human approval required). Red → `gate_failed`. A candidate the gate cannot judge (the diff does not apply, the app does not become ready, Playwright writes no report) is also `gate_failed`, with that reason as the next attempt's `failure_context`, never an infrastructure retry. The gate runs in its own check sandbox (step 4; the tree is `base_commit` + `git apply --cached` of the Coder diff + the sealed bytes), so best-of-N gates never share one. The environment is the image's plus the runner variables; the testability token is a sandbox secret forwarded by name, never in argv. The publisher always builds branch `agent/<KEY>` in the orchestrator checkout (base commit + diff + sealed spec, one commit by `guard-orchestrator`) and the PR text in `.guard/agents/prs/<KEY>.md`; with `[code_host]` and its token configured it then force-pushes that branch and opens or updates a draft PR / MR labelled `agent` (pr-publisher.md). Nothing is ever merged automatically. The integrated gate runs the sealed spec plus `tests/smoke`; the affected-journey selection is not wired into it yet.
9. **Attempts.** `AttemptPolicy` caps Coder attempts at `max_attempts <= MAX_ATTEMPTS = 3` (also the database `CHECK (attempt BETWEEN 1 AND 3)`). After the last failed attempt, or when the attempt's virtual key budget or `timeout_secs` is exhausted (a runtime killed at its timeout, a gateway `budget_exceeded` rejection of a Codex turn), the ticket goes to the human lane without a retry with the full report (diffs, traces, costs). Each attempt mints and revokes its own virtual key.

Copilot coding agent (cloud) PRs get only steps 7-8: `finalize` rejects any change under test paths and overlays the sealed spec.

## Deterministic test-quality checks

Run on the spec's AST (TypeScript compiler API, syntax only) before any model is consulted. `ticket_tag`: every test needs `@ticket:<KEY>`, directly or from an enclosing `describe`; a tag for another ticket also fails. Each check has a stable id reported in `agent_runs.result.quality`:

| Id | Rejects |
| --- | --- |
| `no_focus` | `test.only`, `describe.only`, `it.only`, `fit`, `fdescribe` |
| `no_skip` | `test.skip`, `test.fixme`, `describe.skip`, `test.describe.skip`, `xit`, `xdescribe`, conditional `test.skip(cond)` |
| `no_empty_test` | A `test(...)` whose callback body has no statements |
| `has_expect` | A test with zero `expect(...)` calls (including in `test.step` callbacks it contains) |
| `no_trivial_expect` | `expect(<literal>)` against a literal (`expect(true).toBe(true)`, `expect(1).toEqual(1)`) |
| `no_wait_for_timeout` | `page.waitForTimeout(...)` / any `.waitForTimeout(` call |
| `no_self_mock` | `page.route` / `context.route` whose URL pattern matches the app's own API base (`[app].base_url` or `/api/`) |
| `no_swallowed_assertions` | `try { ... expect ... } catch` without rethrow |
| `no_host_access` | Host access from the spec: imports or `require`/`import()` of Node built-ins (`node:*`, `child_process`, `fs`, `net`, `http`, `os`, ...), a computed `require`/`import()`, `process`, `eval`, `new Function` (defense in depth; red-first and the gate also clear the environment) |
| `ticket_tag` | The `@ticket:<KEY>` tag missing from every `test(...)` (title or `{ tag }` option) |
| `journey_tag_format` | Tags present but not `@ticket:<KEY>` / `@journey:<id>` format |
| `parse_error` | The spec does not parse |

## Outcomes (`agent_runs.outcome`)

`passed`, `gate_failed`, `red_first_passed`, `diff_rejected`, `quality_rejected`, `runtime_error` (any `RuntimeError`). `agent_runs.status` mirrors `result.json` `status` (or `error` when there was no valid result).

## Orchestrator records

After every stage `guard_agents::lane::Orchestrator` writes one `agent_runs` row per attempt (`PgRunLog`, upsert by `(run_id, role, attempt)`), ingests the gateway spend of each attempt's key alias into `spend_records`, puts agent `memory_proposals` in `memory_fact_candidates`, and records its own observations as facts: `ticket/<key>/sealed-spec` (red-first failed on the base) and `ticket/<key>/agent-pr` (the agent branch passed the gate; awaiting approval). Best-of-N candidates share `(run_id, role, attempt)`: only the last one recorded keeps the row (a schema change is needed to keep all).

## Testing

The harness is tested end to end with `FakeAgentRuntime`, `FakeSandboxProvider`, `FakeModelGateway`, `InMemoryMemoryFacts` and `InMemoryEvidenceStore`, with scripted diffs: QA writes a passing spec (red-first rejection), a spec with `test.only` (quality rejection), a Coder diff touching `tests/` (diff rejection), a third failed attempt (human lane), and a tampered sealed copy (hash mismatch aborts the gate).
